# Demo + presentation guide

## DEMO_SCRIPT.md format (storyteller writes it to <round>/deliver/DEMO_SCRIPT.md)
```
# <Product> — demo script (3 min)      Presenter: Umer (talks) · Muizzur (clicks)
Before you start: app open at http://localhost:5173 (landing), deck open in slideshow on slide 1.

0:00 SLIDE 1-2  "Hi, we're Ctrl.Alt.Elite. <problem in one sentence with the big number>."
0:30 SLIDE 3-4  "<Product> does three things: … Here's how it works: …"
1:00 LIVE DEMO  Switch to browser.
     1. Landing: "This is <Product>." (5 s, scroll once)
     2. Click "<primary CTA>" → dashboard: "Live numbers…"
     3. HERO: do <exact clicks/typing with the exact values to enter> → point at <result>.
     4. WOW: <exact steps>.
2:15 SLIDE 6    Results: "<metric 1>, <metric 2>, <metric 3>."
2:35 SLIDE 7-9  "Unlike <today>, we … Next we will …"
2:55 SLIDE 10   "Thank you — happy to take questions."

## If something breaks during the demo
Stay calm, say "let me show you the recorded result" and go to slide 5 (screenshot). Backup: refresh the page —
every screen has fallback data.

## Likely judge questions (with short honest answers)
1. Where does the data come from? → …
2. How accurate is it / how did you test it? → …
3. How is this different from <existing solution>? → …
4. How would it work at scale / in a real deployment? → …
5. What would you build next with more time? → …
6. What was the hardest part? → …
7. Cost to run? → …
```

## Presentation tips for the team (put the short version in the final message to the user)
- One person talks, one person clicks. Decide before you go up.
- Start with the problem number, not "our project is…".
- Live demo > slides. Spend at least 1 minute in the real app.
- Say the numbers slowly. Pause after the big one.
- If you don't know an answer: "Good question — we haven't tested that yet; our next step would be …" (honest beats bluffing).
- Keep the browser zoom at 100-110%. Close other tabs. Turn off notifications (Windows Focus assist).
